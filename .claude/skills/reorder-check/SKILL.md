# 補貨檢查

> 這是**挖空模板**。標 ★ 的地方要你自己填。
> 重點是「數字一定要從盤點資料抄，不能自己編」，而且每個數字都要能驗算。

## 什麼時候用

- 跑完 `npm run simulate`，要決定下一版策略每樣菜備幾份時
- 在瀏覽器玩完一天，想看「倉庫盤點」頁的結果該怎麼調整時

## 資料從哪裡來

在 `web-lab` 資料夾執行：

```text
npm run simulate -- plans/策略檔.json --json
```

每一天的 `inventory` 欄位，是那天每樣上架的菜的盤點：

| 欄位 | 意思 | 怎麼驗算 |
|---|---|---|
| `name` | 菜名 | — |
| `stocked` | 早上備了幾份 | 策略檔裡的 `qty` |
| `sold` | 賣出幾份 | 打烊報表 |
| `waste` | 報廢幾份 | 備貨 − 賣出 |
| `missed` | 賣完之後，還有幾位客人想買卻沒買到 | 客人卡片上「賣完了」的數量 |
| `status` | `ok` 正常、`out` 缺貨、`over` 報廢過多 | 規則書「倉庫盤點」 |
| `suggest` | 明天建議備幾份 | 賣出 ＋ 沒買到 |

## 步驟

1. 執行上面的指令，讀每一天的 `inventory`
2. 先驗算：`waste` 有沒有等於 `stocked − sold`？對不上就停下來回報，**不要用錯的資料做建議**
3. 挑出 `status` 不是 `ok` 的菜
4. 建議備貨量要不要再調整（分成兩層，回報時要分開寫）：
   - **基礎建議**：只依當天資料，規則書算法：賣出 ＋ 賣完後沒買到（`suggest`）。只針對 `out`／`over` 的菜提出；`ok` 的菜不提調整，寫「未調整」。
   - **隔日調整**：只有在使用者提供「隔日需求證據」（例如規則書的明天預告、天氣或事件、星等、宣傳費決定）時，才可以調整，並寫出依據與算式。沒有證據就寫「無隔日證據，不調整」，**不自行加固定百分比**。
   - 調整後的份數仍要符合規則書：整數、全部菜合計最多 80 份、最多上架 4 樣。
5. 同一樣菜連續幾天都缺貨或報廢過多，要怎麼提醒：
   - 同一道菜**連續兩天**狀態都不是 `ok`（缺貨或報廢過多，兩種混合也算），提醒「這是持續現象」，並列出各天的備貨、賣出、報廢、沒買到。
   - 只有一天資料、或兩天之間隔著正常的日子，不推測趨勢，只寫「資料不足以判斷」或照單日處理。
   - 提醒只是提醒，不因此自動多算或少算建議量。
6. 算「建議備貨成本」：建議份數 × 規則書的單份成本，寫出算式（例：22 份 × 35 元 ＝ 770 元）。單份成本只能用規則書菜單表：招牌 35、韭菜 35、玉米 45、酸辣湯 15、豆漿 8、紅茶 8。
7. 判斷「下一版完整備貨能不能執行」：要有**所有**要上架菜的份數、總成本、宣傳費（0／200／500）和可用資金，檢查（a）上架 ≤ 4 樣、（b）總份數 ≤ 80、（c）總成本 ＋ 宣傳費 ≤ 可用資金。缺任何一項，就寫「尚無法確認可執行性」，**不能把單一道菜的建議當成已驗證的完整策略**。
8. 用下面的回報格式回報

## 回報格式

```text
策略檔：
驗算結果：通過 / 第 N 天的 ○○ 對不上（寫出哪個數字）
第 N 天：
  缺貨：菜名 備 … 賣 … 沒買到 … → 建議 …
  報廢過多：菜名 備 … 賣 … 報廢 … → 建議 …
連續現象提醒：菜名 第 A 天（備 … 賣 … 報廢／沒買到 …）、第 B 天（…）→ 持續現象 ／ 只有一天資料，不推測趨勢
建議備貨成本（我想多看的欄位）：菜名 建議 … 份 × 單份成本 … 元 ＝ … 元
下一版每天建議的備貨量：
  基礎建議（依當天資料）：菜名 賣出 … ＋ 沒買到 … ＝ …
  隔日調整：有證據 → 寫依據與算式 ／ 無隔日證據，不調整
可執行性：能確認 → 列出總份數、總成本 ＋ 宣傳費、可用資金與算式 ／ 尚無法確認可執行性（缺：…）
```

## 寫完檢查

- [ ] 每一個數字都能在盤點資料裡找到
- [ ] 備貨、賣出、報廢、沒買到、建議都是非負整數，且賣出沒有超過備貨
- [ ] 報廢 ＝ 備貨 − 賣出
- [ ] 狀態符合規則書：沒買到 > 0 → 缺貨；報廢 ≥ 5 → 報廢過多；其他 → 正常。缺貨和報廢過多同時成立，視為資料矛盾
- [ ] `suggest` ＝ 賣出 ＋ 沒買到
- [ ] 資料缺漏或互相矛盾時，指出**哪一天、哪樣菜、哪個欄位**，並停止提出那一筆的備貨建議（其他沒問題的資料可以繼續）
- [ ] 每個計算出來的數字（建議量、成本、總份數）都列出算式
- [ ] 基礎建議與隔日調整有分開寫；沒有隔日證據就沒有加百分比
- [ ] 連續兩天的提醒有列出各天數字；只有一天資料時沒有推測趨勢
- [ ] 沒有可執行性所需的全部資料時，寫了「尚無法確認可執行性」

## 不准做的事

- 不准修改任何檔案（這個 Skill 只讀不寫，要改策略交給 result-review）
- 不准自己編數字，或用「大概」、「差不多」帶過
- 不准新增或存檔任何東西：分析結果只在對話中回報，不寫成檔案、不改策略檔、不 commit、不 push
- 不准把單一道菜的建議量說成「已驗證的完整策略」

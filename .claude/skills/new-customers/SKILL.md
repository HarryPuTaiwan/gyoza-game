# 客人資料製作

> 這是**挖空模板**。標 ★ 的地方要你自己填，每一格都要寫「理由」。
> 填好之後，AI 每次幫你做客人都會照這份規則，不用你每次重講。

## 什麼時候用

使用者說「幫我做一批新客人」「我要出題考同學」時。

## 每位客人必須有這些欄位

| 欄位 | 意思 | 限制 |
|---|---|---|
| name | 名字 | 不可用真實名人、不可重複 |
| intro | 一句話介紹 | 20 字以內 |
| budget | 一餐的總預算 | 30～150 的整數 |
| wants | 想吃的東西，有先後順序 | 1～2 樣，只能從菜單選 |
| hates | 討厭的東西 | 最多 1 樣，沒有就寫 null |
| days | 出現在第幾天 | 1～5 的整數陣列，例如 [1, 3] |
| count | 當天的基本人數 | 1～12 的整數 |
| lines | 五種情況的台詞 | 每句 20 字以內，五句都要有 |

`lines` 的五種情況：

- `bought`：買到了
- `hated_on_menu`：討厭的東西有上架，不進門
- `not_on_menu`：想吃的沒上架
- `sold_out`：想吃的賣完了
- `too_expensive`：太貴不買

## 菜單（只能從這六樣選）

招牌鍋貼、韭菜鍋貼、玉米鍋貼、酸辣湯、豆漿、紅茶

## 這批客人的主題

★ 主題：預算卡在邊界、又有明確偏好的校園客人（學生、社團、研究生、教授、工讀生）
★ 理由（為什麼選這個主題？）：這批客人是出題關用的，目標是「刁鑽但合規」：每位客人都買得到東西，但只要同學定價偏高、備貨偏少、或上架組合不對，就會被擋在門外。校園客人的預算本來就有限，也容易出現討厭特定食物（吃素、怕韭菜），主題自然，不需要硬編理由。

## 預算範圍

★ 這批客人的預算要落在幾元到幾元之間（必須在 30～150 之內）：50 元～110 元
★ 理由：鍋貼可定價 50～100 元，湯和飲料 15～45 元。預算低於 50 元，連最便宜的鍋貼都買不起，客人永遠買不到，不叫刁鑽。預算高於 110 元，幾乎所有定價都買得起，不會讓同學做取捨。50～110 元正好落在「定價定高就嫌貴、買了第一樣第二樣就買不起」的區間，才有刁鑽的空間。

## 工作步驟

1. 先讀 `web-lab/src/game/menu.js`，確認菜單與建議售價
2. 先產生 3 位客人，用表格給使用者看，**不要直接寫檔**
3. 使用者說 OK，才寫入 `web-lab/src/game/customers/my-customers.json`（整個檔案是一個陣列）
4. 寫完執行下面的檢查，逐條回報結果

## 寫完必須檢查

- 必填欄位都有，五句台詞都有
- budget 在 30～150 之間，也在上面填的預算範圍內
- wants、hates 只用菜單上的品項
- 沒有重複的名字
- 每一天的 count 加總不超過 50
- 在 `web-lab` 資料夾執行 `npm run check`，確認「客人包檢查」仍然全部 PASS
- 打開遊戲，在「客人包」選「我的客人包」，確認沒有出現紅色錯誤
- ★ 我自己加的檢查規則：每位客人的 budget，至少要買得起他 wants 第一樣菜的「最低可定價」（例如想吃玉米鍋貼，budget 至少 60 元；想吃招牌鍋貼，至少 50 元；想吃紅茶，至少 15 元）
- ★ 這條規則要擋掉什麼樣的客人：擋掉「不管同學怎麼定價都永遠買不到」的客人，例如預算 40 元卻想吃玉米鍋貼。這種客人只會讓所有人都得到「不滿」，拉低星等，卻不是靠策略能解的題目，不算刁鑽，只是不公平。

## 不准做的事

- 不准新增菜單沒有的品項
- 不准新增欄位或修改遊戲規則
- 不准改 `my-customers.json` 以外的檔案
- ★ 我自己加的禁止事項：不准讓同一天的所有客人，全部討厭同一樣菜，或全部只想吃同一樣菜
- ★ 理由：這樣同學只要不上架那一樣、或只備那一樣就能全拿或全輸，沒有策略可言，變成猜謎。出題要讓同學有取捨：每天至少要有兩種以上不同想吃的菜，討厭的菜也不能把整天的客人都擋掉。
